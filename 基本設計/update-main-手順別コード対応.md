## ① 対象一覧の確認

- **対象の指定：4行目。** `TARGET_REPOS=("backend" "frontend" "command")` に書かれた順番が処理順になる。
- **空一覧の判定：141〜144行目。** 配列の要素数が `0` ならエラーを表示し、終了コード `1` で終了する。
- **順番に処理する主な操作：146行目。** `for i in "${!TARGET_REPOS[@]}"` が対象を先頭から取り出す。各対象の処理が失敗しても、後続の `continue` によって次の対象へ進む。
- **対象パスの組み立て：6行目、147行目。** `SCRIPT_DIR` はスクリプトの配置場所であり、`repo="$SCRIPT_DIR/${TARGET_REPOS[i]}"` によって対象を探す。実行時の作業ディレクトリには依存しない。

## ② リポジトリごとの確認

| 確認すること | コード | 失敗時の動作 |
| --- | --- | --- |
| 対象ディレクトリがあるか | 152〜155行目の `[[ -d "$repo" ]]` | `add_failure` で記録し、次へ進む |
| 対象ディレクトリ自身が Git リポジトリのルートか | 157〜161行目の `git rev-parse --show-toplevel` とパス比較 | 同上 |

| `origin` の取得先があるか | 174〜177行目の `git remote get-url origin` | 失敗として記録し、次へ進む |

> [!NOTE] 要検証
> **主な操作は152〜176行目の各検証コマンド。** エラーの共通記録は35〜44行目の `add_failure()` が行い、各検証の後の `continue` が次のリポジトリへ進める。未コミット変更を調べる処理、`stash`、変更を破棄する処理はない。そのため、未コミット変更があってもこの段階では失敗にせず、後続の Git コマンドの結果に従う。

## ③ 元のブランチを記録して `main` へ切り替え

- **元のブランチの記録：163〜168行目。** `git symbolic-ref` の結果を `original_branches[i]` に保存し、復帰先として使う。
- **切り替え要否の判定：179〜181行目。** 元から `main` にいる場合は切り替えず、結果表示用に「実行開始時からmain」と記録する。
- **切り替えの主な操作：182〜183行目。** 作業ブランチにいた場合、`git -C "$repo" checkout main` を実行する。
- **切り替え失敗時：183〜190行目。** `add_failure()` で失敗を記録する。現在のブランチが元のブランチと異なる場合だけ `restore_branch()` で復帰を試み、その後は `continue` で次の対象へ進む。
- **切り替え成功時：192行目。** `restore_results[i]` を「復帰待ち」にし、手順④へ進む。

## ④ `main` を更新

**更新の主な操作は196行目の `git -C "$repo" pull origin main`。** 手順③で `main` に移った場合も、最初から `main` にいた場合も、このコマンドを実行する。終了コードが `0` なら197〜198行目で `results[i]` を「成功」にし、失敗なら199〜204行目の処理に入る。`pull` 自体のマージ・リベースなどの動作は、そのリポジトリの Git 設定に従う。

## ⑤ `pull` 失敗時の復帰

- **失敗の記録：199〜200行目。** `add_failure "$i" 'pull失敗'` により、その対象の最終結果を「失敗」にする。
- **復帰するかの判定：201行目。** 実行開始時のブランチが `main` なら切り替えない。作業ブランチだった場合は、**次の対象へ進む前に** `restore_branch "$i"` を呼ぶ。
- **復帰の主な操作：46〜69行目。** `restore_branch()` は、現在のブランチを確認し、必要なら60行目の `git -C "$repo" checkout "$original"` で戻す。成功・失敗は `restore_results[i]` に記録する。強制切り替えは行わない。
- **復帰にも失敗した場合：202行目。** `add_failure()` で失敗理由を追加する。処理が終わると `for` ループが次の対象へ進む。

現状の実装が結果一覧に記録する失敗理由は「pull失敗」という分類であり、Git が出力した詳細なエラーメッセージは保存していない。Git のエラーは実行中のターミナルに表示される。

## ⑥ `pull` 成功時の復帰

- **更新成功の記録：196〜198行目。** `pull` が成功すると `results[i]` が「成功」になる。この時点では作業ブランチへ戻さず、ほかの対象の更新を続ける。
- **全対象の更新後の選別：207〜208行目。** 最初の `for` ループが終わってから、`pull` に成功し、かつ元のブランチが `main` ではない対象だけを選ぶ。
- **復帰の主な操作：209行目と `restore_branch()` の60行目。** 元の作業ブランチへ `git checkout` する。失敗した場合は `add_failure()` により、`pull` が成功していても最終結果を「失敗」に変更する。
- **結果表示：212行目。** `print_summary()` が更新と復帰の結果を表示する。213〜216行目で、全対象が「成功」なら終了コード `0`、一つでも失敗なら `1` にする。

元の作業ブランチへ戻すだけで、更新した `main` をその作業ブランチへマージする処理はない。

## ①〜⑥に共通する処理

- **失敗記録：35〜44行目の `add_failure()`。** 結果を「失敗」にし、失敗理由を追加してエラーログを出す。
- **現在のブランチ表示：26〜33行目の `current_branch()`。** 最終結果で終了時のブランチを示すために使う。
- **結果一覧：71〜110行目の `print_summary()`。** 成功・失敗・未処理の件数と対象を表示する。
- **割り込み時の復帰：112〜139行目の `handle_signal()` と `trap`。** ①〜⑥の途中で中断された場合、記録済みの元ブランチへの復帰を試み、結果を表示して終了する。

## ① 対象一覧の確認

`TARGET_REPO_DIR_NAMES=("backend" "frontend" "common")` に指定した Git リポジトリのルートディレクトリ名を順に処理する。空ならエラーを表示して終了コード `1` で終了する。対象パスはスクリプトの配置場所を基準に組み立てる。

## ② リポジトリごとの確認

| 確認すること | コード | 失敗時の動作 |
| --- | --- | --- |
| 対象ディレクトリがあるか | 156〜159行目 | 失敗を記録して次へ進む |
| 対象直下に `.git` ディレクトリがあるか | 161〜164行目 | 同上 |
| 対象自身が Git リポジトリのルートか | 166〜170行目 | 同上 |
| ローカルの `main` があるか | 172〜175行目 | 失敗を記録して次へ進む |
| `origin` の取得先があるか | 176〜179行目 | 同上 |
| ステージ済み・未ステージの変更があるか | 181〜188行目 | 変更があれば失敗を記録して次へ進む |
| 現在のブランチ名を取得できるか | 190〜195行目 | detached HEAD などは失敗として記録 |

`git status --porcelain=v1 --untracked-files=no` を使うため、未追跡ファイルだけなら事前の失敗条件にしない。状態を取得できない場合も失敗として次へ進む。`.git` がファイルとなる linked worktree は、`.git` ディレクトリの判定で対象外となる。

## ③ 元から `main` かの確認・切り替え

事前確認後の190〜195行目で元のブランチを記録する。元から `main` なら切り替えない。それ以外は201行目で `git checkout main` を実行する。失敗した場合は復帰を試みず、失敗時のブランチを記録して次へ進む。

## ④ `main` を更新

214行目で `git pull origin main` を実行する。終了コード `0` なら成功を記録し、そうでなければ失敗を記録する。マージ・リベースなどの挙動は対象リポジトリの Git 設定に従う。

## ⑤ `pull` の成否判定

214行目で終了結果を判定する。成功なら215〜216行目で更新成功を記録し、⑥へ進む。失敗なら221〜223行目で失敗と「復帰せず」を記録し、元のブランチに戻さず⑦へ進む。失敗時のブランチは `add_failure()` で保存する。

## ⑥ 元のブランチへの復帰

元のブランチが `main` 以外なら、次の対象へ進む前に218行目から `restore_branch()` を呼ぶ。復帰に失敗した場合は、`pull` が成功していても最終結果を失敗にする。元の作業ブランチへ `main` をマージする処理はない。

## ⑦ 次の対象の確認

150行目の `for` ループは指定順に対象を取り出す。各処理の終了または `continue` で次の対象へ進み、全対象を処理すると226行目でループを終える。

## ⑧ 結果一覧の表示

228行目で `print_summary()` を呼び、失敗時に保存したブランチを含む成功・失敗の一覧を表示する。229〜232行目で、全対象が成功なら終了コード `0`、一つでも失敗なら `1` にする。対象一覧が空の場合は145〜148行目で終了する。

## 共通処理

失敗記録とその時点のブランチ保存は36〜46行目の `add_failure()`、結果一覧は73〜111行目の `print_summary()`、割り込み時の復帰は113〜139行目の `handle_signal()` が行う。割り込み時は元のブランチへの復帰を試み、失敗対象のブランチ記録を復帰後の状態に更新する。

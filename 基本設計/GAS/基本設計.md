# 交通費精算 CSV — GAS 版 基本設計

## 構成と共有

Google スプレッドシートにコンテナバインドの Apps Script を置く。ひな形は組織内の利用対象者へ閲覧権限で共有し、利用者は管理用データが空のひな形を各自でコピーする。ルートと明細は利用者のコピー内に保存する。コピーにはスクリプトも含まれるため、ひな形を更新した場合、既存のコピーへの反映は更新時に別途扱う。 [コンテナバインドスクリプト](https://developers.google.com/apps-script/guides/bound)

`onOpen()` で「交通費精算」メニューを追加する。各メニュー項目は HTML Service のモーダルを開き、画面からは `google.script.run` でサーバー処理を非同期に呼ぶ。 [カスタムメニュー](https://developers.google.com/apps-script/guides/menus) · [モーダルダイアログ](https://developers.google.com/apps-script/guides/dialogs) · [サーバー関数の呼び出し](https://developers.google.com/apps-script/guides/html/communication)

## シート定義

各シートの1行目を見出し、2行目以降をデータとする。配布するひな形には見出しを設定しておく。

| シート名 | 列範囲 | 見出し順 |
|---|---|---|
| `マイルート` | A:J | ルートID、ルート名、出発、到着、往復、金額/Km、客先請求、申請理由、交通機関、備考 |
| `精算明細` | A:I | 日付、出発、到着、往復、金額/Km、客先請求、申請理由、交通機関、備考 |

`マイルート` のルートIDには新規登録時に生成した UUID を使う。フォームではルート名を表示し、修正対象や一括登録に使う対象はルートIDで特定する。`精算明細` には、確定時のルートの各値と生成した日付を保存する。精算明細の日付列は `YYYY-MM-DD` の文字列を保持できる書式をひな形で設定する。

## マイルート登録（G01）

同じモーダルで「新規」または既存ルートを選べるようにする。既存ルートを選ぶと登録済みの値を表示する。保存時は入力をサーバー側で再検証し、新規なら末尾に1行追加、修正ならルートIDで特定した1行を更新する。

| 項目 | 入力ルール |
|---|---|
| ルート名 | 前後の空白を取り除いた結果が空欄ならエラー。同じ名前の別ルートがある場合もエラー。 |
| 出発、到着 | テキスト。 |
| 往復 | `片道`、`往復`、`--`。 |
| 金額/Km(片道分) | 片道分を半角数字で入力する。空欄も可。 |
| 客先請求 | `なし`、`あり`。 |
| 申請理由 | `通勤費(通常勤務地)`、`在宅チャージ`、`営業関連(業務説明等)`、`社内業務(面談・会議等)`、`健康診断`、`内勤業務／採用関係`、`内勤業務／その他※要備考入力`、`その他※要備考入力`。 |
| 交通機関 | `--`、`電車（国内）`、`バス（国内）`、`その他※原則使用不可`。 |
| 備考 | 任意のテキスト。備考が必要と表示される申請理由は、保存前に利用者が内容を確認する。 |

マイルート登録画面では「金額/Km(片道分)」と表示する。シートとCSVの列見出しは「金額/Km」とし、「往復」を選んだ場合も入力した片道分の値を明細に転記する。

入力ルール資料は選択肢の出典として使う。自由入力欄の必須条件や長さの制限は、上表で明示した検証を適用する。 [交通費精算の入力ルール](../../../../csv-editor/csv_editor_app/交通費精算_入力ルール.csv)

## 明細一括登録（G02）

1. モーダルの初期表示で `マイルート` を一括取得し、候補ごとにルートID・ルート名・登録内容の照合用の値を返す。画面にはルート名を表示する。一覧が空の場合は確定を無効にし、登録用モーダルを案内する。
2. 利用者はルートと開始日・終了日を入力する。モーダルは日付範囲に含まれる月曜〜金曜を数えて表示する。開始日と終了日は両端を含め、平日に当たる祝日も含める。日付は暦日として処理する。
3. 確定時にルートID・開始日・終了日・選択時の照合用の値を GAS に渡す。サーバー側で日付の妥当性、順序、両端を含めた範囲の上限（1,000日）、対象平日数（1日以上）、シートと見出しを検証する。確定時に同じルートIDの行から照合用の値を再計算して比較する。ルートが削除・変更されていた場合は、最新の候補を選び直せるように登録を中止する。
4. `精算明細` の使用済み範囲からA:Iの既存行をまとめて読み込み、生成予定の行と照合する。日付は `YYYY-MM-DD` に揃え、他の項目は CSV に出力される値として比較する。9列が一致する行が1件でもあれば、該当日を表示し、書き込み前に処理全体を中止する。同じ日付でも他の項目が異なる明細は登録できる。
5. 検証・照合を通過した行を日付の昇順に並べ、末尾の連続した範囲へ1回の `setValues()` で書き込む。ドキュメントロック内で対象の再確認、重複チェック、追記を行う。先頭が `=` の文字列は、書き込み時に先頭へアポストロフィを付けて数式としての評価を防ぐ。結果は追加件数を返す。 [LockService](https://developers.google.com/apps-script/reference/lock/lock-service) · [バッチ操作](https://developers.google.com/apps-script/guides/support/best-practices)

モーダルは処理中に確定ボタンを無効にする。成功時は追加件数を表示し、失敗時は入力を保持して理由を表示する。応答が途切れて結果が不明な場合は `精算明細` を確認してから再実行する。

## CSV 作成と受入確認（G03）

利用者は `精算明細` を開き、行を確認・修正し、提出対象だけが載っていることを確認してから Google Sheets の標準操作で CSV をダウンロードする。現行実装に合わせて生成日付は `YYYY-MM-DD` とし、入力ルール資料の `yyyy/MM/dd` との差は、提出先への取り込み試験で確認する。 [Google Sheets のダウンロード操作](https://support.google.com/docs/answer/49114?hl=ja) · [現行 CSV の見出し](../../../../csv-editor/csv_editor_app/交通費精算_申請データテンプレート.csv)

| 確認項目 | 受入条件 |
|---|---|
| 組織内での共有 | ひな形作成者とは別の組織内アカウントでコピーを作り、メニューから2つのモーダルを使える。コピーに追加したルートと明細は、配布用ひな形に反映されない。 |
| ルート保存 | 新規ルートが1行追加される。修正時に同じIDの行が更新される。不正なルート名、同名、半角数字以外の金額/Km(片道分)は保存されない。往復のルートでも、入力した片道分の値が明細の「金額/Km」に入る。 |
| 平日の生成 | 金曜〜月曜で2行を追加する。平日の祝日も1行作成する。土日だけ、逆順、1,000日超では0行。 |
| 重複と再実行 | 生成予定の1日分でも同一の明細がある場合は全件を止める。同日で内容が異なる明細は登録できる。処理中に確定を連打しても1回分だけが記録される。 |
| CSV の互換性 | 9列の見出しと順序、日本語の値、`YYYY-MM-DD` の日付を維持し、標準ダウンロードで取得した CSV を実際の提出先で取り込める。 |
